# 코드 리뷰는 결함 탐지 이상의 조율·거버넌스 과정이다

## 한 문장 인사이트
이 글은 **AI 에이전트가 코드 리뷰를 대체할 수 있는지**에 대해 코드 리뷰가 결함 탐지를 넘어 **조율·의미 형성·거버넌스 과정**이라는 주장을 제시한다. 근거는 **리뷰어가 코드를 이해하지 못하는 상황 자체가 신호라는 관찰**이고, 한계는 정량적 근거가 제시되지 않은 점이다. 내 작업에서는 **우리 리뷰가 실제로 어떤 기능을 하고 있는지 분류해 보는 것**을 확인해 보겠다.

## 원문 요약
코드 리뷰를 결함을 찾는 작업으로만 보면 자동화 가능한 일로 보이지만, 실제로는 **조율·의미 형성·거버넌스 과정**이라고 본다.
따라서 에이전트가 리뷰의 개별 기능을 수행할 수 있다는 사실만으로 **사람을 대체할 수 있다고 볼 수 없다**고 주장한다.
숙련된 리뷰어가 코드를 이해하지 못하는 상황은 리뷰어의 역량 문제가 아니라, 그 **코드의 복잡성·추상화·의도에 문제가 있다는 신호**로 읽는다.
즉 리뷰 과정에서 생기는 '이해 실패'는 제거할 잡음이 아니라 **설계 정보로 취급**한다.
글은 에세이 형태이며, 실험이나 **측정 수치는 제시되지 않는다**. (원문에 없음)

## 핵심 주장과 근거
- 주장 1: 코드 리뷰의 기능은 결함 탐지에 국한되지 않고, 변경의 조율, 코드 의미에 대한 **합의 형성**, 무엇을 머지할지 정하는 거버넌스를 포함한다.
- 주장 2: 리뷰의 개별 기능을 에이전트가 수행 가능하다는 것과, 리뷰 전체를 사람 없이 돌릴 수 있다는 것은 **다른 명제**다.
- 근거: 숙련된 리뷰어가 코드를 이해하지 못하는 상황이 복잡성·추상화·의도의 문제를 드러낸다는 경험적 관찰. 이 신호는 **사람이 읽을 때만 발생**한다.
- 한계·반론: 벤치마크나 조직 데이터 없이 관찰과 논증에 기댄 에세이다. 어떤 리뷰 유형(단순 린트성 지적 등)은 실제로 자동화가 낫다는 반론에는 **직접 답하지 않는다**.

## 읽고 얻은 관점
- 리뷰 자동화를 논할 때 대상이 '결함 탐지'인지 '합의 형성'인지 **먼저 갈라야 한다**. 섞어 두면 도구 도입 효과가 **과대평가**된다.
- '리뷰어가 못 읽는 코드'를 설계 결함 신호로 쓰는 관점은 유용하다. 에이전트가 문법·패턴을 통과시켜 버리면 **이 신호가 사라진다**.
- 에이전트 리뷰의 실질 효과는 사람 리뷰어의 **주의력을 어디로 옮겼는지**로 봐야 한다. 지적 건수 감소는 지표가 되기 어렵다.

## 적용 질문
- 우리 저장소의 리뷰 코멘트를 **결함 지적 / 설계 의문 / 맥락 공유**로 분류하면 비중이 어떻게 나오는가.
- AI 리뷰 도입 후 사람 리뷰어가 코드를 '이해하지 못했다'고 말하는 빈도가 줄었는가, 아니면 **말할 기회가 없어졌는가**.
- 머지 결정 권한(거버넌스)은 어디까지 사람이 쥐고 있어야 하는가를 **문서로 정해 두었는가**.
