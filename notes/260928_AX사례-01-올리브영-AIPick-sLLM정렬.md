## 한 문장 인사이트
이 기업은 **추천 카드 문구가 형식·자연스러움·상품 적합성을 함께 못 맞추는** 병목을 풀려고 **카드 생성 sLLM의 정렬 학습·평가 단계**에 AI를 적용했고, 성과는 **형식 통과율·사람 선호율**로 확인해야 한다(전환 지표는 원문에 없음). 확산의 관건은 **평가 기준 검증**이며, 우리 서비스에 적용한다면 **출력 형식 검증기**부터 해보겠다.

## 원문 요약
- AI Pick은 상품 상세 정보로 추천 카드 문구를 LLM이 자동 생성하는 지면이다. 파이프라인은 상세 이미지 OCR → 특징 추출(상품 특징/사용 팁/적합 대상) → 카드 생성 → 이미지 생성 순이며, 글은 카드 생성 단계의 **WHO(개인화)·TPO(계절·시간·장소) 모델**만 다룬다.
- 카드는 JSON 배열, 필드별 글자 수(15~24자)·어미·톤, 브랜드·상품명 금지, 원문에 없는 효능·성분 금지, 과장·의학적 보장 금지 규칙을 지켜야 한다. 출발점은 **Gemma3-4B-it에 SFT**를 한 모델이다.
- SFT 후에도 형식 위반과 "**자연스럽지만 상품과 안 맞는 문구**"(뷰러 고무에 "다양한 색상으로 연출")가 남았다.
- 형식은 규칙 검증기로, 자연스러움·문맥적합은 외부 모델의 NLL로 수치화해 **사람 라벨·LLM Judge 없이** 선호 쌍을 만들고 DPO를 학습했다. DPO로 무너진 형식은 **formatmix와 GRPO로 보정**했다.

## 적용 구조와 성과
- **대상 업무와 병목:** 추천 지면에 그대로 노출되는 카드 문구 생성. 형식 규칙 위반과 상품에 안 맞는 문구가 함께 남았다.
- **적용 단계:** 카드 생성 모델의 post-training(DPO·GRPO)과 평가.
- **방식:**
  - 형식: 규칙 검증기로 통과/폐기(**hard gate**). 검사 항목은 길이·어미·JSON·슬롯 범주다.
  - 품질: Polyglot-Ko-1.3B의 NLL로 자연스러움(nll_nat)·문맥적합(nll_ctx)을 수치화해 선호 쌍을 자동 구성하고 DPO를 학습했다.
  - 보정: WHO는 near-miss 오답을 섞는 formatmix(0.25), TPO는 형식 보상 GRPO.
  - 운영: 정렬 모델 + **검증기 기반 재시도**의 하이브리드.
- **성과 (자체 측정, 홀드아웃 테스트):**
  - 초기 검증 통과율(형식 중심): Gemini 2.5 Pro 프롬프팅 WHO 55.4%·TPO 43.0%, **SFT 4B 모델 81.1%·78.5%**.
  - DPO 후 품질 프록시는 좋아졌으나 형식 통과율은 **WHO 86.7%→62.8%, TPO 76.4%→37.6%로** 떨어졌다. 보정 후 **WHO 76.0%, TPO 62.3%까지** 회복했다.
  - 블라인드 사람 평가 약 2,000건과의 정합성: **NLL AUROC 0.694**, Gemini 2.5 Pro 판정 0.599.
  - retry@5만으로 형식 통과율 **98% 이상**, 추론 비용은 **약 5배**.
  - 구매 전환율·클릭률 등 비즈니스 지표: **원문에 없음**.

## 읽을 때 주의할 점
- 모든 성과는 홀드아웃 테스트의 형식 통과율, NLL 프록시, 사람 평가 선호율이다. 구매 전환율·클릭률 등 비즈니스 지표는 원문에 없다.
- 형식 통과율만 보면 정렬 후에도 SFT가 앞선다(TPO 62.3% vs 76.4%). 원문은 형식 실패는 추론 시 재시도로 복구할 수 있다는 이유로 이 절충을 택했다.
- 과장·의학적 보장 금지, 원문에 없는 효능 금지를 규칙으로 어떻게 걸렀는지는 원문에 없다. 사실성은 nll_ctx라는 간접 프록시로만 다룬다.
- 원문은 결론을 "짧은 한국어 UI 문구" 과제 범위로 한정했고, 문맥적합 축은 평가자 간 일치도가 낮았다고 밝힌다.

## 읽고 얻은 관점
- "좋은 추천 카드"를 형식 준수 / 자연스러움 / 문맥적합 **세 축**으로 나누고, 축마다 다른 도구(규칙 검증기, NLL 프록시, 사람 평가)로 쟀다. 정의를 먼저 쪼개야 측정할 수 있다.
- 품질과 형식은 **같이 움직이지 않았다**. 한 지표만 보고 모델을 바꾸면 다른 축이 무너진다.
- **평가 체계 자체가 자산**이다. 같은 검증기+NLL이 학습 데이터 생성, 실험 비교, 최종 평가에 모두 쓰였다.

## 적용 질문
- 내 서비스의 LLM 출력 품질을 **몇 개의 축**으로 나눌 수 있고, 축마다 무엇(규칙·프록시·사람 평가)으로 재는가?
- 모델이나 프롬프트를 바꿀 때 **한 축의 개선이 다른 축을 떨어뜨리지 않는지** 함께 보는 지표표가 있는가?
- 오프라인 품질 지표와 별도로, 노출 후 클릭·전환 같은 서비스 지표와 **금지 표현 위반률**을 추적하고 있는가?
