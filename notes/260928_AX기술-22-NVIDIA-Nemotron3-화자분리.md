# 화자 분리는 받아쓰기가 아니다 — NVIDIA Nemotron 3 Diarization으로 본 "누가 언제 말했나"

## 한 문장 인사이트
이 글은 회의·통화 전사에서 **"누가 언제 말했나"를 붙이는 문제**에 대해 **ASR과 분리된 1억 파라미터 화자 분리 모델 하나로 오프라인·스트리밍을 모두 처리하는 방법**을 제시한다. 근거는 VoiceArena 1위(DER 14.72%)와 자체 8개 데이터셋 비교이고, 한계는 **화자 라벨이 익명 채널일 뿐 신원이 아니고 최대 8명까지**라는 점이며, 내 작업에서는 **녹음 파일 한 개로 버퍼 지연별 DER과 겹침 구간 처리**를 확인해 보겠다.

## 원문 요약
- NVIDIA NeMo 음성팀이 오픈 웨이트 화자 분리(diarization) 모델 **Nemotron 3 Diarization(약 100M 파라미터)** 을 공개했다. 최대 **8명**의 화자를 녹음·실시간 대화 모두에서 구분한다.
- 화자 분리는 **말한 내용이 아니라 각 화자가 말한 시간 구간**을 낸다. 단어는 ASR이 내고, 둘을 타임스탬프로 합쳐야 화자별 전사가 된다.
- 출력은 `[T, 8]` 확률 텐서다. 두 사람이 동시에 말하면 같은 프레임에서 두 채널이 함께 켜져 **겹침 발화**를 자연스럽게 표현한다.
- 화자 채널은 **처음 등장한 순서**로 번호를 매긴다(Sortformer 방식). 스트리밍에서는 화자 캐시(AOSC)와 FIFO 큐가 이전 청크의 화자 정보를 유지한다.
- 같은 모델을 입력 버퍼 **30.4초·1.04초·0.64초·0.32초** 네 설정으로 돌린다. 짧을수록 빨리 응답하지만 정확도와 처리량이 떨어진다.
- 라이선스는 OpenMDW 1.1. Argmax Pro SDK 3, Baseten, DigitalOcean이 지원을 발표했다.

> "These are anonymous labels, not real-world identities."
> (이 라벨은 익명 채널이지 실제 신원이 아니다.)

## 핵심 주장과 근거
- **주장 1: 화자 분리와 ASR은 다른 작업이고 따로 평가해야 한다.**
  - 근거: 화자 분리 오류는 놓친 발화·잘못 감지한 발화·화자 혼동·경계 오류이고, ASR 오류는 단어 오류다. 원문 예제는 단어 중간 시점에 활성 화자가 하나면 그 화자, 둘 이상이면 `overlap/ambiguous`, 없으면 `unassigned`로 붙이는 **단순 정렬 규칙**을 쓴다. 이 규칙은 겹친 목소리를 분리하지 못한다고 원문이 밝힌다.
- **주장 2: 공개 벤치마크에서 가장 낮은 오류율을 냈다.**
  - 근거: VoiceArena 초기 Diarization-Bench(12개 시스템·17개 설정, 영어 대화 139건·약 22시간, 겹침 채점, 경계 허용 0)에서 **DER 14.72%로 1위**, 2위는 19.3%. 원문은 **v1 평가가 끝나면 바뀔 수 있다**고 적는다.
  - DER = (놓친 발화 + 오탐 + 화자 혼동) ÷ 전체 기준 화자 시간. 경계 허용(collar)·겹침 채점 여부에 따라 값이 크게 달라진다고 원문이 강조한다.
- **주장 3: 이전 4인용 모델보다 정확하고 빠르다.**
  - 근거(자체 평가, 비교 대상 diar_streaming_sortformer_4spk-v2.1): 1.04초 지연에서 8개 평가 조건 모두 DER 감소, 상대 감소 9.0%(CALLHOME-Part2)~65.2%(NOTSOFAR1 MHM). 8개 상대 감소의 **단순 평균 41.0%** 이며 전체를 합친 DER이 아니다.
  - 처리량(RTX PRO 5000, BF16, 배치 32, torch.compile): 30.4초 설정에서 **RTFx 15,113배 대 2,619배**, DIHARD III DER 19.09%→12.73%. 1.04초 설정에서 865배 대 136배.
  - 학습 데이터에 David AI 라이선스 데이터를 추가해 DER이 11.19%→10.42%로 줄었다.
- **한계·반론:**
  - 2인 CALLHOME 부분집합에서는 **5.98%로 이전 모델(5.68%)보다 나빴다**. 개선은 화자가 많은 구간에서 크다.
  - 8명을 넘으면 발화를 놓치거나 채널을 잘못 배정한다. 잡음·잔향·원거리 마이크·도메인 이동·긴 대화에서도 오류가 늘 수 있다.
  - 지연 수치는 **입력 버퍼 시간**이다. 모델 연산·네트워크·ASR·앱 처리는 포함하지 않는다. RTFx는 배치 처리량이지 단일 스트림 지연이 아니다.

## 읽고 얻은 관점
- 회의록·상담 요약에서 "누가 약속했나"를 뽑으려면 좋은 ASR만으로는 부족하다. 화자 분리는 별도 모델·별도 지표(DER)·별도 오류 유형을 가진 독립 단계다.
- 화자 분리는 신원 확인이 아니다. `speaker_2`를 실제 사람에 연결하려면 회의 메타데이터, 사용자 프로필, 화자 검증 모델 같은 **다른 단계**가 필요하다.
- 스트리밍 설계는 지연·정확도·처리량을 한 설정값(청크+오른쪽 문맥)으로 교환하는 문제다. 제품 요구(응답 속도)를 먼저 정하고 운영점을 고르는 순서가 맞다.
- 벤치마크 수치는 평가 조건(경계 허용, 겹침 채점, 평균 방식)과 함께 읽어야 한다. 원문이 "평균 40% 감소"를 "조건별 상대 감소의 단순 평균"이라고 직접 풀어 준 점이 좋은 예다.

## 적용 질문
- 작은 실험: 3~4명이 말한 16kHz 모노 회의 녹음 10분을 사람이 화자 구간으로 라벨링한 뒤, 30.4초·1.04초·0.32초 설정으로 각각 돌려 **DER과 겹침 구간 비율**을 비교한다. 같은 녹음에 Parakeet ASR을 붙여 `overlap/ambiguous`로 빠지는 단어 비율도 센다.
- 내 서비스에서 화자 라벨 오류가 결과를 바꾸는 지점(액션 아이템 담당자, 발언 요약)은 어디이고, 불확실한 배정을 사용자에게 어떻게 보여 줄 것인가?
- 실제 이름을 붙여야 한다면 화자 채널과 신원을 잇는 근거(참석자 목록, 등록 음성)를 어디서 가져오고, 동의 절차는 어떻게 둘 것인가?

## 읽을 때 주의할 점
- 모델 개발사(NVIDIA)가 쓴 글이다. 이전 모델 대비 개선 수치는 자체 평가다.
- VoiceArena 순위는 **초기 결과**이며 v1 평가·통계 분석 뒤 바뀔 수 있다고 원문이 밝힌다.
- 지연 수치(0.32~30.4초)는 입력 버퍼 시간이지 사용자가 체감하는 전체 지연이 아니다.
- 데모의 8인 시나리오 일부는 짧은 화자 문맥을 먼저 들려준 합성 음성이라 벤치마크가 아니다. Argmax의 비교(OpenBench, 6개 시스템·11개 데이터셋)는 파트너사 인용이다.
- 실제 서비스 도입 성과(회의록 품질 개선 등)는 원문에 없음.
