# OpenAI, Codex의 에이전트 하네스와 실행 인프라를 Agents API로 공개했다

> 정리일: 2026-09-28
> 출처: [OpenAI — Introducing the Agents API](https://openai.com/index/introducing-the-agents-api/)
> 발행일: 2026-09-10
> 원문 언어: 영문

---

## 한 문장 인사이트
OpenAI는 **에이전트를 직접 조립하던 흐름이 관리형 런타임으로 옮겨 가는 흐름**을 **Codex의 하네스·샌드박스를 API로 공개한 제품 발표와 고객 인용**으로 설명한다. 이는 에이전트를 만드는 개발팀에게 **오케스트레이션을 직접 만들지, 맡길지를 다시 정해야 한다**는 의미이며, 확인된 사실은 **퍼블릭 베타 출시와 토큰·도구 사용량 과금**이고 성능 개선 수치는 **고객사의 자체 측정 주장**이다.

## 원문 요약
- OpenAI는 Codex를 움직이는 하네스(컨텍스트 관리·도구 사용·서브에이전트 조정)와 실행 인프라를 **Agents API**로 묶어 **퍼블릭 베타**로 공개했다.
- 작업·모델·도구·환경을 지정하면 **API 호출 한 번으로 에이전트 세션**을 만든다. 하네스는 OpenAI가 호스팅·유지한다.
- 실행 환경(샌드박스)은 **OpenAI 호스티드 샌드박스, 자체 인프라, 파트너 샌드박스** 중에서 고른다. 파트너는 Blaxel, Cloudflare, Daytona, DigitalOcean, E2B, Modal, Oracle, Runloop, Vercel이다.
- 하네스 기능으로 **컨텍스트 자동 압축(compaction)**, **도구 검색(tool search)**, **프로그래머틱 도구 호출**, **서브에이전트 병렬 위임**을 제공한다. MCP, 커스텀 함수, 웹 검색 같은 내장 도구를 지원한다.
- 하네스는 오픈소스 Codex 코드베이스 기반이라 핵심 로직을 들여다볼 수 있다. **추가 요금 없이 토큰과 도구 사용량만 과금**한다.

## 주장과 사실 구분
- **발행처의 주장·제품 소개**
  - 모델이 나올 때마다 하네스를 버전 단위로 함께 개선하므로, 개발자는 하네스 재작업 없이 성능 향상을 얻는다는 주장이다.
  - 자동 압축으로 여러 컨텍스트 창에 걸친 긴 세션을 개발자가 압축 로직 없이 이어 간다고 설명한다.
  - 도구 검색은 필요한 도구 정의만 불러와 토큰 비용을 줄이고 캐시를 보존한다고 설명한다.
  - 서브에이전트는 각자 컨텍스트를 갖고 병렬로 일하며, 메인 에이전트가 결과를 모은다.
- **원문에 실린 고객사 인용(모두 자체 측정)**
  - Ciridae: 평가 점수 **0.71 → 0.85**, 서브에이전트 흐름으로 **지연 4배 감소**.
  - SafetyKit: 케이스 검토 워크플로 이전 후 **건당 비용 60% 감소**, 기존 성능 유지.
  - Hypha(금융): 하네스와 샌드박스를 분리해 **실패한 에이전트 응답 86% 감소**.
  - Dwelly: 수백 개 에이전트를 비동기로 펼쳐 **몰리는 작업량(bursty workload)**을 유휴 인프라 없이 처리.
  - Nash.ai: 물류망에서 수천 개의 장기 실행 에이전트를 운영하며 세션 유지·복구 계층으로 쓴다.
- **내가 더 확인할 것**
  - 고객 수치의 비교 기준(이전 구성, 표본, 기간)은 원문에 없다.
  - 자체 인프라·파트너 샌드박스를 쓸 때 로그·트레이스를 어디까지 볼 수 있는지, 비용 구조가 어떻게 달라지는지.
  - 베타 기간의 제한(세션 길이, 동시 실행 수, 지원 모델)과 GA 일정.

## 읽고 얻은 관점
- 에이전트의 경쟁 지점이 모델 자체에서 **하네스(컨텍스트·도구·서브에이전트 운영)**로 옮겨 가고 있다. OpenAI는 그 하네스를 제품으로 팔기 시작했다.
- **하네스는 공급사, 환경·데이터·UX는 우리 것**이라는 분리가 발표의 핵심 구조다. Long Lake 인용("Agents API supplies the harness; the environment, context, and UX stay ours")이 이를 그대로 보여 준다.
- 샌드박스를 VPC·자체 인프라에 둘 수 있게 한 것은 보안·망분리 요구가 있는 기업을 겨냥한 선택으로 읽힌다.
- 추가 요금이 없다는 것은 곧 비용이 **토큰 사용량에 그대로 연동**된다는 뜻이다. 서브에이전트를 늘리면 비용도 함께 는다.

## 적용 질문
- 지금 직접 짠 도구 호출 루프 중 컨텍스트 압축·재시도·서브에이전트 조정처럼 **관리형 런타임이 대신할 수 있는 부분**은 어디인가?
- **작은 실험:** 읽기 전용 리서치 과제 하나(예: 공개 문서 5건 요약·비교)를 정해, 직접 만든 tool-calling 흐름과 관리형 런타임에 똑같이 20회씩 돌리고 **성공률, 소요 시간, 비용, 오류 복구 여부, 로그 가시성**을 표로 비교한다.
- 하네스를 공급사에 맡겼을 때 **모델·하네스 버전이 바뀌면 결과가 달라지는 문제**를 어떻게 고정하고 회귀 테스트할 것인가?

## 읽을 때 주의할 점
- 공급사(OpenAI)의 제품 발표 글이다. 성능 개선 수치는 모두 고객사 인용이며 비교 조건이 공개되지 않은 자체 측정이다.
- 퍼블릭 베타 단계다. 원문도 GA를 향해 피드백을 받아 빠르게 바꾸겠다고 쓴다. 기능과 조건이 바뀔 수 있다.
- "API 호출 한 번으로 프로덕션 준비된 에이전트"는 발행처의 표현이다. 실제 운영에 필요한 평가·권한·감사 체계는 원문에서 다루지 않는다.
