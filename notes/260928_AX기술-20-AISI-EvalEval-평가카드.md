# 영국 AISI가 벤치마크 결과를 설정 정보와 함께 Evaluation Cards로 공개했다

> 정리일: 2026-09-28
> 출처: [Hugging Face Blog — How UK AISI and EvalEval Are Making Benchmark Results Reproducible](https://huggingface.co/blog/evaleval-aisi)
> 발행일: 2026-09-22
> 원문 언어: 영문

---

## 한 문장 인사이트
이 글은 **같은 벤치마크 점수라도 평가 설정이 달라 비교·재현이 어렵다**는 문제에 대해 **결과와 설정·맥락을 공통 스키마(Every Eval Ever)와 공개 플랫폼(Evaluation Cards)에 함께 기록하자**는 방법을 제시한다. 근거는 **영국 AI Security Institute가 5개 벤치마크·6개 프런티어 모델의 검증된 결과를 이 구조로 공개한 사례**이고, 한계는 **채택이 아직 일부 평가 기관에 머물러 있다**는 점이다. 내 작업에서는 **모델 평가 결과마다 추론 예산·프롬프트·채점 방식을 같이 기록하는 양식**을 확인해 보겠다.

## 원문 요약
- EvalEval Coalition은 영국 AI Security Institute(AISI)가 EvalEval의 인프라로 평가 결과를 공개하기 시작했다고 발표했다.
- 두 기관은 NeurIPS 2025 공동 워크숍에서 협업을 시작했고, AISI의 피드백이 공통 보고 스키마 **Every Eval Ever(EEE)** 설계에 반영됐다.
- AISI는 논문 *How Inference Compute Shapes Frontier LLM Evaluation*의 주 실험 결과를 **Evaluation Cards**에 올렸다. 대상은 HealthBench, FrontierMath, Humanity's Last Exam, SWE-Bench Pro, Terminal-Bench 2.0의 **5개 벤치마크**와 Claude Opus 4·4.5·4.6, GPT-5·5.2·5.4의 **6개 모델**이다.
- 사이버 평가 두 종(Cyber CTFs, The Last Ones)의 결과도 함께 공개했다. 모델 구성은 일부만 겹친다.
- 공개물에는 검증된 결과, 맥락, 설정(configuration) 정보가 들어 있다.

## 핵심 주장과 근거
- **주장: 평가 결과는 설정 정보 없이는 재현도, 비교도 어렵다.**
  - 근거: 평가 결과가 여러 형식·플랫폼·매체에 흩어져 보고되고, 재현에 필요한 정보가 빠진 경우가 많다. 다시 돌리는 비용도 크다.
  - AISI 논문은 벤치마크 성능이 **추론 시점 연산량과 평가 프로토콜**에 따라 달라진다는 것을 다룬다. 원문 그림에서 Humanity's Last Exam은 매 시도 후 정답 여부 피드백(오라클)을 받으면 토큰 사용이 늘수록 더 많은 문제를 풀었다.
  - Terminal-Bench 2.0에서 AISI의 결과를 같은 모델에 대한 다른 기관의 보고치와 나란히 놓아, 평가 설정 차이를 보여 준다.
- **방법: 공통 스키마 + 해석 가능한 카드**
  - Every Eval Ever: 평가 결과를 담는 공통 스키마이자 저장소.
  - Evaluation Cards: 벤치마크 메타데이터, 평가 실행 데이터, 모델 메타데이터를 하나의 해석 가능한 기록으로 묶는다. 비슷해 보이는 점수가 **서로 다른 조건에서 나왔는지** 알아보게 하는 것이 목적이다.
  - AISI의 다른 작업(OptStop: 평가 효율화, HiBayES: 계층 베이지안 통계)과 이어진다.
- **한계·반론**
  - 원문은 모델 개발사·평가 개발사·연구자에게 참여를 요청하는 단계다. 몇 곳이 채택했는지는 원문에 없다.
  - 공개는 "적절한 경우(where appropriate)"로 한정된다. 무엇이 공개 범위에서 빠지는지는 원문에 없다.

## 읽고 얻은 관점
- 벤치마크 점수 한 줄은 **"어떤 추론 예산과 프로토콜에서"라는 조건이 붙어야 의미가 있다**. 같은 모델이라도 설정이 바뀌면 순위가 바뀔 수 있다.
- 정부 평가 기관이 결과를 **표준 스키마로 공개**하면, 다른 보고치를 해석하는 기준점이 생긴다. 규제·조달에서 벤치마크를 근거로 쓸 때 중요해진다.
- 평가 결과를 "보고서 속 숫자"가 아니라 **메타데이터가 붙은 데이터**로 다루자는 흐름이다. 모델 카드가 모델에 한 일을 평가 쪽에서 하려는 시도로 읽힌다.

## 적용 질문
- 내가 모델·프롬프트를 비교할 때 기록하는 항목에 **추론 예산(최대 토큰·시도 횟수), 프롬프트 버전, 채점 방식, 피드백 여부**가 모두 들어 있는가?
- 공급사 발표 벤치마크와 내 평가 결과가 다를 때, 차이를 설정 차이로 설명할 정보가 양쪽에 있는가?
- 팀 내부 평가 결과를 Every Eval Ever 같은 공통 스키마로 남기면 몇 달 뒤 재비교가 쉬워지는가?

## 읽을 때 주의할 점
- EvalEval Coalition이 자기 프로젝트 채택을 알리는 글이다. 스키마의 효과를 따로 측정한 결과는 없다.
- 추론 연산량과 성능의 관계에 대한 구체적 수치는 AISI 논문에 있고, 이 글에는 그림 설명만 있다.
- 모델 목록은 AISI가 평가한 특정 버전들이다. 평가 시점과 설정은 Evaluation Cards 원자료에서 확인해야 한다.
